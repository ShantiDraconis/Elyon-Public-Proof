# Cross-problem bridge boundary — RH ↔ complexity

STATUS: **CANDIDATE BRIDGES ONLY / NO MATHEMATICAL PROMOTION**

The current `m-core-riemann` state records
`endpointPropositionTyped = false`. Therefore even the classical RH endpoint
must be typed before a theorem can connect it to the P-vs-NP discriminant.

## Candidate implications

The audit recognizes the following shapes as legitimate research obligations:

- `RH -> D`, where `D := NP ⊆ P` in the P-vs-NP repository;
- `RH -> ¬D`;
- `RH -> factoringPolynomialTime`;
- `twistedZetaOffCritical -> ¬D`.

None is asserted as an existing theorem.

## Proposed twisted-zeta route

A symbolic proposal such as

`ζ_D(s) = ∏_p (1 - D·p^{-s})^{-1}`

is not yet a mathematical bridge because `D` is currently a proposition in
the P-vs-NP core, not a scalar parameter. Before this expression can be used,
the project must supply, at minimum:

1. a typed parameter replacing/proxying the proposition `D`;
2. a definition of the Euler product and its domain of convergence;
3. analytic continuation/meromorphic structure as needed;
4. a precise definition of `offCritical`;
5. a theorem connecting the analytic statement back to `D` or `¬D`;
6. a fixed-model complexity theorem transporting that result to P vs NP.

Without all six, the formula is notation, not an orientation witness.

## Existing external status

RH and P vs NP are separately listed as Millennium Prize Problems. This audit
contains no known theorem deriving either P=NP or P≠NP from RH, and no theorem
deriving polynomial-time factoring from RH.
